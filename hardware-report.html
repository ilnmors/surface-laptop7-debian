Wi-Fi 실기기 장애 복구

Surface RFKILL 보정 두 개를 보존한 ath12k D044C56077CC5357DC3F5BF를 서명·로드했습니다. 차단 없음·인증·IP 할당·반복 Wi-Fi 지정 HTTPS 200을 확인했고 오프라인 재빌드도 같은 srcversion을 재현했습니다. 2026-11-13 장애 분석: 09:05:40 연결 AP의 채널 전환(CSA, ch36·20MHz) 5초 뒤부터 펌웨어 통계 요청 타임아웃(time out while waiting for fw stats done)이 6초마다 1,296회 이어졌고, 11:20 절전 때 멈춘 뒤 복귀 시 펌웨어 재적재 후에는 0회였습니다. 10:28 단절(약 40초)도 DFS 채널(ch124) 전환 직후였습니다. 11:46 복귀 뒤 새 장소에서는 어느 AP든 몇 초 만에 비콘 손실·해제가 반복됐고(비콘 손실 17·해제 22·TX flush 실패 3), 12:53 재부팅 뒤 같은 계열 AP에서 안정적입니다.

검증·다음 단계

원인 후보: ath12k의 채널 전환 처리 버그로 펌웨어 또는 호스트 드라이버 상태가 망가짐(채널 전환과의 시간 상관이 뚜렷함). 복귀 뒤 반복 단절은 펌웨어 재적재 후에도 이어져 호스트 쪽 상태 잔존을 의심하지만 미확정입니다. cma 영향은 낮음: qmi dma 할당 실패 메시지는 정상 동작 중인 cma=0 부팅에서도 나옵니다. 재발 시 직전 CHANNEL-SWITCH 여부를 확인하고, 재부팅 대신 ath12k_wifi7 모듈 재적재로 회복되는지 봅니다. 근본 대책 후보는 새 펌웨어(현재 WLAN.HMT.1.1.c7-00108, 2026-03-06)나 ath12k CSA 수정이 들어간 커널이며, 재현을 한 번 더 확보한 뒤 진행합니다. 이전 기록: 11/12~13 deep 절전 3회는 비콘 손실 없이 약 2초 안에 재연결했습니다.

설치와 기록

python3 setup.py --plan으로 실행 범위를 확인하고 bash setup.sh로 전체 설치합니다. python3 setup.py --component desktop처럼 선택할 수도 있습니다. 각 디렉토리의 setup.sh와 setup.py는 같은 구현을 사용합니다.

Console의 Caddy·Kopia·code-server·계정은 별도 repository에서 관리합니다. 최초 MOK 등록, 펌웨어 설정, 재부팅과 로그인은 수동입니다. 미해결 하드웨어 동작과 Steam 전체 런타임·개인 데이터 복원까지 자동화됐다는 뜻은 아닙니다.

설치 절차 · 다른 Debian에 적용하는 범위 · 출처와 패치 · 이어갈 작업

HTML도 Git에 저장하고 작업마다 갱신합니다. scripts/docs/configuration만 Git에 저장하며, 실제 오프라인 복구에는 무시된 바이너리 파일도 함께 복사해야 합니다.
